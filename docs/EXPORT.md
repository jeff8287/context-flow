# 실험용 내보내기

프로젝트의 세션 몇 개를 그 순간의 모습 그대로 한 파일에 담습니다. 실험 참가자 모두가 같은 기록을 같은 화면으로 보게 하려는 것입니다. 내보낸 기록은 읽기만 합니다. 거기서는 말을 보낼 수도 조각을 걸어 둘 수도 없습니다.

## 두 가지 파일

| 파일 | 든 것 | 여는 법 |
|---|---|---|
| 화면 파일 (`.html`) | 화면과 기록이 한 파일에. 밖에서 아무것도 가져오지 않습니다 | 두 번 눌러 브라우저로 엽니다. 서버도 설치도 필요 없습니다 |
| 묶음 파일 (`.json`) | 기록만 | 이 도구의 '묶음 파일 열기…', 또는 화면을 정적으로 올린 곳에서 `?bundle=파일.json` |

## 만드는 법

화면에서 내보낼 세션만 지도에 켜고, 왼쪽 위의 내보내기 단추를 눌러 '화면 파일로 내보내기' 또는 '묶음 파일로 내보내기'를 고릅니다. 켠 세션과 거기 딸린 서브에이전트·곁가지 대화가 들어갑니다. 타일을 손으로 옮겨 두었으면 그 자리도 함께 갑니다. 프로젝트 여럿을 함께 올린 지도도 그대로 내보냅니다.

같은 메뉴의 '내 이름 가리고 내보내기'를 켜면 이 컴퓨터 사용자의 이름(홈 폴더 이름)이 가려집니다. 그 아래 칸에 더 가릴 낱말을 쉼표로 적습니다. 화면에 보이는 기록은 바뀌지 않고 내보내는 파일만 가려집니다.

명령줄에서도 됩니다.

```sh
npm run build                      # 화면 파일은 빌드된 화면을 넣으므로 먼저
npm run export -- <프로젝트> --sessions <id 앞머리>,<id 앞머리> --out 기록1.html
npm run export -- <프로젝트> --out 전체.json          # --sessions 를 빼면 프로젝트의 세션 전부
npm run export -- <프로젝트>,<프로젝트> --out 둘.html  # 여러 프로젝트를 한 지도로
npm run export -- <프로젝트> --out 가림.html --mask --mask-words 낱말,낱말
```

명령줄로 내보낸 파일에는 옮긴 타일의 자리가 없습니다. 자리는 화면을 연 브라우저가 기억하기 때문입니다.

데모로 해 보려면 `npm run demo`를 띄운 화면에서 내보내기 단추를 누르면 됩니다.

## 무엇이 들어가고 무엇이 빠지나

**들어가는 것.** 고른 세션의 요청·답변·변경 원문 전부, 그 세션들 사이의 연결(갈라짐, 서브에이전트, 도착한 조각, 붙여넣기 흔적), 같이 고친 파일. 고르지 않은 세션의 글은 한 글자도 들어가지 않습니다. 고른 세션에서도 고치거나 되감아 버려진 말(대화에 접혀 보이는 것)은 들어가지 않습니다. 원문이 그대로 들어가므로 내보내기 전에 세션에 민감한 글이 없는지 확인하세요.

**빠지는 것.** 고르지 않은 세션과 그쪽으로 가는 연결, 걸어 두고 아직 도착하지 않은 조각, 기록 파일의 경로.

**멈춘 것.** 상태(작업 중, 답 기다림, 몇 시간 전)는 내보낸 순간의 것입니다. 작업 중이던 세션은 그때의 상태 그대로 담기되 움직이지 않게 그려지고, 묶음 이름이 '작업 중 · 내보낼 때'가 되고, '알아둘 것'에 그 세션의 기록이 거기까지라고 적힙니다. 끝난 대화만 보이려면 세션이 모두 멈춘 뒤에 내보냅니다.

**같은 시작.** 열면 내보낼 때 켜 두었던 세션이 지도에 올라 있고, 손으로 옮겨 둔 타일은 그 자리에 있고, 밝기도 내보낼 때의 것으로 시작합니다. 참가자가 바꿀 수는 있습니다. 세션의 색은 켠 순서로 정해지므로 모두에게 같습니다.

**가려지는 것** (이름 가리기를 켰을 때). 낱말은 대소문자를 가리지 않고, 요청·답변·변경의 원문, 세션과 프로젝트의 이름, 폴더와 파일 경로 어디에 있든 같은 글자 수의 '•'로 덮입니다. 글자 수가 같아서 연결이 가리키는 구간(`start`, `end`, `parts`)은 가리기 전과 같습니다. id와 도구의 낱말(`kind`, `client` 등)은 그대로입니다. '알아둘 것'에 몇 곳을 가렸는지 적힙니다.

**가려지지 않는 것.** 적어 주지 않은 낱말입니다. 성과 이름을 띄어 쓴 글, 이메일 주소, 저장소 주소처럼 사용자 이름과 다르게 적힌 것은 낱말을 더 적어야 합니다. 내보낸 뒤 파일에서 직접 찾아 확인하세요.

## 내보낸 화면에서 되는 것

지도(확대 단계 포함), 세션 켜고 끄기, 대화 읽기, 찾기, 선을 눌러 넘어간 것 보기, 나온 자리와 받은 자리, 글을 골라 역추적, 시간 흐름이 됩니다. 이어 쓰기, 조각 보내기와 걸어 두기, 새 세션, 기록 다시 읽기는 되지 않습니다.

## 묶음 파일의 꼴 (분석할 때)

```
{ "kind": "context-flow-bundle", "version": 1, "madeAt": <ms>,
  "snapshot": { "project", "sessions": [...], "items": [글 없는 항목 목록], "links": [...], "overlaps": [...], "notes": [...] },
  "items": [ { "id": "<세션 id>:<번호>", "sessionId", "kind": "prompt|answer|change", "at": <ms>, "text", "path"?, "added"? } ],
  "view": { "on": [처음 켜질 세션 id], "theme": "light|dark", "spots": [[세션 id, x, y], …] } }
```

- `links[].grade`는 `recorded`(기록에 남은 것) 또는 `paste`(글자를 견줘 찾은 것)입니다. `kind`는 fork, spawn, subagent, side, import, transfer, paste 가운데 하나입니다.
- `links[].from`과 `to`는 세션, 항목, 글자 범위(`start`, `end`)입니다. 붙여넣기는 `parts`에 맞은 구간들이 있습니다.
- `view.spots`는 손으로 옮긴 타일의 자리(지도 좌표)입니다. 옮긴 것이 없으면 없습니다.
- `snapshot.projects`는 여러 프로젝트의 지도에서 내보냈을 때만 있습니다. 그때 `sessions[].projectId`가 그 가운데 하나를 가리킵니다. 한 프로젝트의 묶음에서는 모든 세션의 `projectId`가 묶음의 id(`bundle:…`)입니다.
- 꼴의 정의는 `packages/core/src/bundle.ts`와 `model.ts`에 있습니다.

## 확인한 것과 못 한 것

확인한 것은 다음과 같습니다.

- 내보낸 화면을 이 도구의 서버가 내주는 주소로 열어, 서버에 아무것도 묻지 않고 지도·대화·찾기·역추적이 도는 것.
- 묶음 파일을 화면에서 열고 다시 실제 기록으로 돌아오는 것, `?bundle=`로 여는 것.
- 타일을 옮기고 이름을 가려 내보낸 화면에서 타일이 옮긴 자리에 있는 것.
- 실제 기록에서 사용자 이름 560곳이 모두 가려지고 글자 수와 연결의 범위가 그대로인 것.
- 두 프로젝트를 담은 화면에 테 둘과 그 사이의 선이 나오는 것, 작업 중이던 세션이 멎은 채 나오는 것.
- 자동 시험. 고른 세션만 들어가는지, 파일에서 다시 읽은 묶음이 서버와 같은 답을 내는지, 화면 파일이 밖의 것을 가리키지 않는지.

화면 파일을 두 번 눌러(file://) 여는 것은 확인하지 못했습니다. 시험에 쓴 브라우저가 file:// 주소를 열지 못하게 되어 있었습니다. 참가자에게 주기 전에 한 번 직접 열어 보세요.
